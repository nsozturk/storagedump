# Chrome Web Store — Submission Guide for StorageDump

Complete step-by-step checklist for publishing StorageDump.

---

## 0. Pre-Flight Checklist

Before uploading, confirm these are done:

- [ ] `npm run build:prod` — clean production build in `dist/`
- [ ] `npm run pack` — creates `storagedump.zip` (the file you upload)
- [ ] Privacy policy is hosted at a public URL (see §5)
- [ ] At least 1 screenshot (1280×800) ready in `store/screenshots/`
- [ ] Extension loads and works correctly in Chrome with "Load unpacked"

---

## 1. Create a Developer Account

1. Go to <https://chrome.google.com/webstore/devconsole>
2. Sign in with a Google account
3. Pay the one-time **$5 registration fee**
4. Accept the Developer Agreement

---

## 2. Upload the Extension Package

1. Click **"New Item"**
2. Upload `storagedump.zip` (generated by `npm run pack`)
3. Wait for Chrome to parse the manifest — it will pre-fill some fields

## 4. Privacy Practices Tab

### Privacy policy URL
You **must** host the privacy policy at a public URL because the extension requests `cookies` + `<all_urls>`.

**Option A — GitHub Pages (recommended):**
1. Push `store/privacy-policy.html` to your repo
2. Enable GitHub Pages on the repo (Settings → Pages → `main` branch / `docs` folder OR use the file directly)
3. URL will be: `https://<username>.github.io/<repo>/store/privacy-policy.html`

**Option B — GitHub raw URL:**
```
https://raw.githubusercontent.com/<username>/<repo>/main/store/privacy-policy.html
```
(Chrome may not render it nicely, but it's accepted as a policy URL)

**Option C — Gist:**
Create a GitHub Gist with the HTML content and use its URL.

Enter the URL in the **Privacy policy URL** field.

### Single purpose description
```
StorageDump reads and exports browser storage data (cookies, localStorage, sessionStorage, IndexedDB, Cache API) for the tab the user is currently viewing. No data leaves the user's device.
```

### Data usage (check all that apply)
- ✅ **Personally identifiable information** — the extension reads cookies which may contain PII
  - Purpose: **User-initiated inspection only** (not for any other purpose)
  - Transfer to third parties: **No**
  - Transfer for unrelated uses: **No**
  - Sold: **No**
  - Collected by the developer: **No** (data never leaves the user's machine)

> CWS Note: Even though you're NOT collecting data, you must still answer these questions because the extension *accesses* PII-adjacent APIs (cookies). Answer "Yes, but only to provide core functionality" and explain that data is processed locally only.

## 5. Permissions Justification Tab

Chrome will flag these permissions and ask you to justify them. Use these responses:

### `cookies`
```
The extension's core purpose is to read and display cookie data for the active tab. Without the cookies permission, the cookie category would be completely non-functional. Cookies are only read on user demand (when the popup is opened or an export is triggered) — never in the background.
```

### `<all_urls>` (host permission)
```
Users need to inspect storage for any arbitrary website they visit, not just a predefined list. The extension cannot know in advance which sites a user will want to inspect. The <all_urls> permission is used exclusively for two purposes: (1) reading cookies for the current tab via chrome.cookies.getAll, which requires a URL parameter matching the site; and (2) injecting the in-page bridge script via chrome.scripting.executeScript to read localStorage, sessionStorage, IndexedDB, and Cache API — APIs that are only accessible from the page's JavaScript context. The script is injected only when the user actively opens the popup or requests an export.
```

### `scripting`
```
Reading localStorage, sessionStorage, IndexedDB, and Cache API requires running JavaScript in the page's context. These APIs are not accessible from the extension background. The script is injected only on explicit user action and only reads data — it does not modify any page state.
```

### `tabs`
```
The extension needs to identify which tab is active in order to read storage for the correct site. After a scan the user starts, the extension icon shows a count for that tab; tabs.onUpdated clears it when the tab navigates. No page is read in the background.
```

### `downloads`
```
When the user clicks "Export", the extension generates a ZIP or JSON file in memory and saves it to the user's Downloads folder via chrome.downloads.download. This is the only way to trigger a file save from a service worker context in Manifest V3.
```

### `storage`
```
User preferences such as the default export format and export options, plus metadata about past exports (file name, size, checksum), are kept locally via chrome.storage so they survive browser restarts. No storage contents of the inspected sites are kept there.
```

### `activeTab`
```
Used to get metadata (URL, title) for the currently active tab when the popup is opened, without requiring permanent broad access.
```

### `web_accessible_resources` (reviewer question)
```
Only three specific files are declared web-accessible:
- assets/inpage.js  — the in-page bridge script injected via scripting.executeScript
- assets/constants.js  — small constant lookup table imported by inpage.js
- assets/serialization.js  — tiny data-serialization utility imported by inpage.js

These three files are the only ones that need to be loadable from page context.
No other extension assets (background.js, popup.js, dashboard.js, CSS, etc.) are
web-accessible. The bridge script only reads the page's own storage — data the
page already has full access to — so making it web-accessible does not grant any
capability escalation.
```

## 7. Review Expectations

Because this extension requests `<all_urls>` + `cookies`, it will receive **enhanced review** (human review, not just automated). This normally takes **1–3 business days** for new submissions, up to a week.

Common rejection reasons and how we've addressed them:
- ❌ "Permission not justified" → addressed in §5 above
- ❌ "No privacy policy" → addressed in §4
- ❌ "Remote code execution" → ✅ no `eval()`, no remote scripts
- ❌ "Misleading description" → ✅ description accurately reflects functionality
- ❌ "Extension does not work as described" → test thoroughly before submitting

---

## 8. After Approval

- CWS assigns a permanent extension ID — update `README` if you have one
- You can update the extension by incrementing the `version` in `manifest.json`, running `npm run pack`, and uploading a new zip via the developer dashboard
